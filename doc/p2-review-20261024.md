## 3. 重点契约核对

- **日历/首次边界：** 短月和 DST 算法不变；保留 400 年日期模型。新增首次允许边界延后至五月、二至四月普通唤醒均零 API/零账本，再在五月执行一次的正向验证。另实际模拟一月完成后从 22 日改为 1 日，二月不清零、三月按 period 2 执行，旧周期摘要不变；不能用显示月份或新 revision 获得额外清零机会。
- **稳定所有权：** 不改变 task/host/panel/inbound 稳定身份，修改仍 revision+1；remove 保留 tombstone。旧 revision 不重新激活；此前的 prepared 新建取消身份预留继续有效。
- **意图与防重复：** 每个 POST 前 pending 提交、每步单次请求、确认后不可变、全量预检与阶段读回继续保留。30 场景文件/head 故障矩阵仍覆盖意图、确认和最终提交；不存在“所有步骤 confirmed 就可以补写/补发”的自动路径。
- **多 Client：** 1/2/16 Client、个人无限额 stop、hold、本人有限额度耗尽、入口单独到额恢复等既有用例复验。配额和 Client 顺序不硬编码 Basic/Core；入口额度不能代替个人恢复条件。3.7.0 / 3.10.2 的字段及副作用模型未被此次修正改写。
- **timer 与故障：** 不发送 service start/restart；有限月日历、Persistent=false、Restart=no、稳定锁 inode、固定目标路径等适配器契约保留。失败可发生在 timer 已启用之后，日志必须报告实际状态；失败记录阻断执行，不冒称 timer 已自动暂停。
- **只读和凭据：** check/audit 不创建锁、账本或缓存；audit 无 Token/API。Token 仍不进入 argv、计划或账本，管理流程只持有读取接口。真实 systemd/curl POST 全部使用替身。

## 4. 版本和接续边界

配置 v1、事件 v1、执行账本 v2 的 schema 名称不变，解析校验收紧。`0.2.0a2` 是本地源码复查版本，**不是已部署 `0.2.0a1` 的原位升级操作**：程序摘要守卫继续拒绝未经 P3 版本切换的程序替换；没有重签、重写或导入任何真实历史。

可恢复的 prepared 预检失败与已经开始的失败事务有不同边界。后者只读审计可提供证据，但 P2 仍没有半安装自动恢复、程序回退、r2 导入或凭据轮换入口。完整一致的外部快照回卷无法仅凭本地哈希链可靠检测；服务端没有请求幂等键，GET/POST 间也不存在条件更新保证。

完成级别限定为 L1：真实 Linux root/权限、flock、目录 fsync、systemd 日历及 LoadCredential、断电、真实两版面板、Xray 与代理业务影响仍属于未完成的 L2/L3。当前测试不能代替真实自然账期验收。

本地最终检查包括：98 项标准库测试（204.176 秒）、30 个持久化故障场景、12 次只读回环 GET、Python 3.11 语法、版本与文档链接、差异与敏感字面量扫描、44 份测试期间代码/测试/元数据摘要、5 份已批准及历史基线原字节核对。没有执行真实 POST、SSH、systemctl/systemd-analyze、VPS 操作、commit、push 或发行；P2 中相应系统接口仅用替身验证。
