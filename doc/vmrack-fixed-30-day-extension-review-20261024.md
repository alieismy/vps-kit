## 2. 核对后保持不变的结论

- 三台独立参数正确：18 刀 1000 GiB 候选商家预算、锚点 `2026-11-16T02:05:00Z`；35 刀 600 GiB、`2026-11-09T01:50:00Z`；49 刀 1000 GiB、`2026-11-20T02:35:00Z`。这是沿用用户单位约定的计算值，不代替部署前确认 VMRack 字节基数。
- 原版面板、二倍中转估算、零预留条件下的父/单 Client 候选额度分别为 500/300/500 GiB；不覆盖既有配额，不套用于 traffic.2。商家当前用量与面板当前用量不能互相替代。
- 日唤醒为固定 UTC 时分秒，30 天业务边界是其子集；执行授权、first 和防重账本决定是否可以清零。`OnUnitActiveSec` 相对上次激活，不能保持商家锚点。[systemd timer 252](https://www.freedesktop.org/software/systemd/man/252/systemd.timer.html)
- VMISS Basic/Core 保留每月 22 日 Toronto 时间及 DST，不能通用化成固定 UTC/30 天；r2/V2.1.2 历史继续走已有来源契约。
- Client quota-recovery 依本人额度，父池到额不能代替；hold 不重置；父入口 reset 与 enable 分别按动作防重。每步持久化 pending、无自动重试、240 秒写窗口及漏期未来处置保留。
- 官方说明支持购买/续费起点的 30 天周期，但续费后的真实锚点仍要核实。[VMRack 计费说明](https://www.vmrack.net/zh-CN/docs/vps/billing)
- 本轮重新读取的 traffic.2 README 和补丁证实原始/计费计数及余数、增量倍率和 reset 相关修改；当前配置解析器确实拒绝 `3.7.0+traffic.2`。保持定制写适配延期，不承诺倍率与商家账单严格等价，不借版本后缀替换绕过适配。
