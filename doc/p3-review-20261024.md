# P3 复查记录

日期：2026-10-24。被评基线 `0.3.0a1 / P3-1`，修订目标 `0.3.0a2 / P3-2`。范围包含源码、契约、测试和本地开发包；约束是零 VPS 连接、零真实清零、零实际 timer/service 操作。原开发包、测试记录和修改前副本保留在忽略目录；批准方案与 VMISS 生产材料不修改。

复查修订已完成：冻结源码一次完整回归 134 项全通过，确定性包与同源码一致性核对通过。没有遗留阻断本轮本地交付的已确认问题。

本记录是工程复查及本地验证证据，不构成 Linux/systemd/真实面板部署批准。最终结果统一见 [P3 验证记录](p3-validation.md)，对外接口见 [P3 契约](p3-contract.md)。

## 1. 已复现并修正的问题

| 严重度 | 原行为及影响 | 修正与回归定位 |
|---|---|---|
| 高 | 旧发行目录被改动时，回退先暂停并将 `current` 指向旧版本，随后才验证并报错；稳定入口可能已指向损坏代码 | [deployment.py](../src/vps_kit/traffic/deployment.py) 在任何暂停/目标写入前核验旧包全部文件；反例确认失败后指针、日志、凭据及 timer 均不变 |
| 高 | 部署后完成 P2 配额修订，再回退凭据时按旧配置恢复文件并 GET，直到配额不匹配才报错 | 回退预检要求 owner 活动及当前配置摘要/修订仍与原部署一致；业务修订不属于程序/凭据回退范围。原生历史和配置不恢复旧快照 |
| 高 | schema 1 来源 manifest 未核对原 Inbound/Client 绑定与 `old_cycle`；删除整对旧 marker 后仍能导入 | [legacy.py](../src/vps_kit/traffic/legacy.py) 严格核对已知 manifest 结构、四文件摘要集合、套餐、原对象绑定、紧邻 first_cycle 的已完成旧周期、所有 `state_before` 原字节。非对象旧状态返回受控错误 |
| 高 | `isatty()` 为真不保证可关闭终端回显；标准库 `getpass` 在失败时会警告并降级为可见读取 | [deploy_commands.py](../src/vps_kit/traffic/deploy_commands.py) 将 `GetPassWarning` 变为立即失败；测试用实际 `fallback_getpass` 验证可见读取函数从未调用 |
| 中 | `--save` 可以指向尚不存在的活动凭据、unit 或管理文件，绕过该目标应有的事务入口 | [native.py](../src/vps_kit/traffic/native.py) 对 P2/P3 计划及隐藏凭据候选共用目标边界：拒绝新旧管理树、锁、固定入口和 systemd unit 目录，仍允许管理区外的受保护新文件 |
| 中 | 包校验未拒绝文件/目录前缀冲突，缺少固定 CLI 文件也能通过部分结构检查；文件镜像的 link/absent 分支跳过祖先目录校验 | [package.py](../src/vps_kit/traffic/package.py) 增加前缀冲突与入口必需项；[deploy_files.py](../src/vps_kit/traffic/deploy_files.py) 在所有文件镜像分支先检查受信祖先。异常包在安装前拒绝 |
| 中 | 回退读取大批旧包/备份后，没有在暂停前再次核对时间窗口 | 校验备份之后重新核对 NTP、单调时钟和 900 秒维护窗口；模拟慢读取跨入禁区时，保持原 timer/文件/日志不变 |

首批反例在旧实现上运行 4 个测试方法，出现 7 个预期失败（其中一个方法包含多项 manifest 反例），日志 `regressions-before.log`。这些失败用于证明缺陷，不作为通过证据。新增反例和组合场景见 [test_p3_review.py](../tests/traffic/test_p3_review.py)。

## 2. 全面核对范围

- **安装/切换**：新装双版本面板契约、已存在的不可变版本、部分目录、陈旧计划、暂停状态保留、显式 enabled、主机绑定前置、配置不随程序升级改变。
- **r2 混合历史**：Basic/Core 各自预算、身份、日历和原 first_cycle；同时包含 V2.1.2 schema 1 与 r2 schema 2 的合成历史，导入后仅授权下一自然周期，不伪造或重发旧成功账本。
- **双锁/退役**：新锁→旧锁顺序、争用释放、稳定 inode 契约、磁盘与生效 mask、旧 runner 拒绝入口、旧状态集合/备份漂移、跨进程升级和凭据轮换复用最初退役证据。实际 Linux flock 仍未验证。
- **回退**：旧版本损坏、配置修订、备份损坏、手工漂移、旧 unit 归档与 mask 之间中断、文件替换/日志提交故障、新 pending 后回 r2；历史永不覆盖，回 r2 始终暂停。
- **凭据/只读边界**：无命令行明文、无真实凭据，隐藏输入失败停止，候选路径隔离、Token 轮换/撤销模型、部署审计零 API/写入，不从 GET 推断 admin 权限。
- **开发包**：最终全量回归源码冻结摘要、包内源码逐字节一致、确定性双构建、完整清单、链接、Python 3.11 AST、解包后双版本合成只读发现及无 pyc。

## 3. 保留的边界

没有修改 P1 双版本字段规则、P2 清零请求顺序、最多一次请求语义、未决跨月阻断或多人配额恢复规则。r2 解析器独立读取旧数据，不执行备份 runner。没有以宽松字段或删除历史绕过迁移门槛。

程序/凭据回退不能用于撤销后续 P2 配置修订；这种情况需要单独核对当前配置和恢复目标。已完成旧周期不会因重新安装、改 UUID、回退版本或轮换 Token 而被重新授权。完整一致的整机快照回卷和无服务端幂等键仍属于既定保证边界。

Debian 13/12、Ubuntu 24.04 × 3X-UI 3.7.0/3.10.2 六组合，以及 LoadCredential、真实权限/符号链接/锁/目录 fsync、断电、自然 systemd 触发、真实 API 与代理业务验收均保持未验证。当前只交付本地开发包，不部署或发布。
