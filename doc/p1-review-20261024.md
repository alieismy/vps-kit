# P1 实现与契约复查

日期：2026-10-24。基线 `0.1.0a1`，修正后 `0.1.0a2`，契约 P1-2。范围为 P1 源码、契约和测试；不进入 P2，不部署、不连接 VPS、不清零、不调整 timer/service。

结论：**本次发现的 P1 问题已修正，并通过本地复验；只能视为 P1 本地实现和契约核对通过，不能用于宣称生产就绪或真实双版本运行验收。** 原有 43 项测试复跑通过，但新反例仍暴露了兼容性、输入边界、状态查重和中断清理遗漏。

文档采用 rd-review 的设计评审维度；代码用实际反例和回归测试验证。本次由同一代理完成自检及整改，没有独立外部评审或生产验收。严重度 Major 表示影响 P1 承诺的兼容、安全或核心契约；Minor 表示错误处理或参数解释缺陷。

## 2. 双版本与多 Client 结论

模型依据：[v3.7.0 model.go](https://github.com/MHSanaei/3x-ui/blob/v3.7.0/internal/database/model/model.go)（blob `5e2db9dc8d14eefab1405b5a4edae1a5a4fd19a2`）和 [v3.10.2 model.go](https://github.com/MHSanaei/3x-ui/blob/v3.10.2/internal/database/model/model.go)（blob `18c61158f766d35e484f4cb4086370445bba431a`）。两版 NodeID 都使用指针加 omitempty，OriginNodeGuid 空值也被省略；缺键兼容只按这些明确字段定义开放。[源码索引](p1-source-evidence.json) 保留其余路由、字段和副作用顺序来源。

- 3.10.2 的 embedded resetWeekday 缺键继续报 `EMBEDDED_WEEKDAY_MIGRATION_UNVERIFIED`。没有隔离迁移证据，不将它自动当成 0。
- resetDay、trafficResetDay、resetWeekday、resetMax 的含义继续分开；两层额度分别校验，不引入 Basic/Core 分支。
- Client 集合精确匹配；记录 ID/UUID/Email 分别唯一，单 Client 只关联目标入口；多 Client 个人配额之和可以超过入口共享池。
- stop 要求配置态和 traffic 态均启用；quota-recovery 仅在本人有限额度耗尽时允许禁用态；hold 要求两态禁用并跳过本人。入口到额不授权恢复所有 Client。
- `quota-recovery-eligible` 是快照条件，不证明禁用原因，不执行启用。因手动操作而禁用但刚好已经到额的 Client，仍可能满足这个显式策略；需要保留禁用时应选择 hold。
- 两版本未来 Client reset 的启用顺序差异仅是元数据，P1 没有写 API；本次没有验证真实到额恢复或 Xray 重启。

## 3. 只读、凭据与历史边界

curl 的数字 IPv4 规范化见 [官方 URL 语法](https://curl.se/docs/url-syntax.html)；`--connect-to` 只改变网络连接目的地而保留 TLS/SNI 的定义见 [官方选项说明](https://curl.se/docs/manpage.html#--connect-to)。本地反例仅使用表示 127.0.0.1 的数字地址，不用公网地址验证旁路。

Token 仍仅从受保护文件进入受控 stdin，不进入 curl argv、报告或异常；不支持任意请求路径、重定向、自动重试、代理或 TLS 跳过验证。GET 成功仍不证明 admin scope。root:root 0600 和祖先目录规则保留；真实 Linux 文件权限行为尚未验证。

测试证据也作了修正：父进程 audit hook 不会自动继承到 CLI 子进程，因此现在为该子进程单独加入网络、文件写入和子进程启动守卫。测试启动器明确设置与正式入口一致的 `__main__.__file__`；Windows subprocess audit 的 executable=None 形式单独识别，不能把测试入口崩溃计为产品通过。

只读动作不主动写配置、报告、锁或账本，但不承诺操作系统访问时间、系统审计、面板访问日志和缓存完全不变。多个 GET 不是原子快照，正常计数增长无需相等或归零。后续执行器仍须进行写前复核。

历史查重现在按逐目标键，但其输入只包含调用方提供的记录。`continuity=NOT_PROVEN`、`automatic_replay=FORBIDDEN` 保留；缺失历史、伪造新面板身份、注册回卷、锁与断电恢复均不是 P1 已解决的问题。r2 导入与回退保持 P3 边界，未新增执行接口或自动补写账本。
